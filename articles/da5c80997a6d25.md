# 概要

`fontkit`を使うと、フォントファイルから文字ごとの幅や位置情報を取得したり、グリフをSVGのパスへ変換したりできます。

今回はGoogle Fontsの「Noto Sans JP」を使って、テキストをSVGとして出力する方法と、少し応用して文字を円形に並べる方法を試してみます。

## fontkit

> Fontkit は、Node およびブラウザ向けの高度なフォントエンジンであり、PDFKit でも採用されています。多くのフォント形式、高度なグリフ置換やレイアウト機能、グリフパスの抽出、カラー絵文字グリフ、フォントのサブセット化などをサポートしています。

引用元：[fontkit公式README](https://github.com/foliojs/fontkit)

https://github.com/foliojs/fontkit

主な機能

- [TrueType](https://ja.wikipedia.org/wiki/TrueType) (.ttf)、[OpenType](https://ja.wikipedia.org/wiki/OpenType) (.otf)、[WOFF](https://ja.wikipedia.org/wiki/Web_Open_Font_Format)、WOFF2、TrueType Collection (.ttc)、およびDatafork TrueType (.dfont) フォントファイルに対応
- 文字をグリフにマッピングする機能をサポートしており、合字やその他の高度な置換機能にも対応
- グリフのメトリクスの読み取りやグリフのレイアウトに対応しており、カーニングやその他の高度なレイアウト機能もサポート
- グリフ置換（GSUB）や位置指定（GPOS）などの高度なOpenType機能
- [Apple Advanced Typography](https://en.wikipedia.org/wiki/Apple_Advanced_Typography) (AAT) のグリフ置換機能
- グリフのベクトルパスを取得し、それらをSVGパスに変換したり、グラフィックスコンテキストにレンダリングしたりする機能のサポート
- TrueType（glyf）およびPostScript（CFF）のアウトラインに対応
- AppleのSBIXテーブルやMicrosoftのCOLRテーブルを含む、カラーグリフ（例：絵文字）のサポート
- AATバリエーショングリフに対応しており、ウェイトや幅、その他の要素について、ほぼ無限のデザイン制御が可能
- フォントのサブセット化のサポート - 指定したグリフのみを含む新しいフォントを作成

# 実際に試してみる

今回は [Google Fonts](https://fonts.google.com/) で「Noto Sans JP」をダウンロードして使ってみます。ダウンロードした `Noto_Sans_JP.zip` を開くと中に `static/NotoSansJP-Regular.ttf` があるのでそちらを使います。

## 動作環境

```bash
$ bun --version
1.3.4
```

## プロジェクト作成

```bash
$ bun init
✓ Select a project template: Blank
...
$ bun add fontkit
$ bun add -D @types/fontkit
```

プロジェクトのルートに `NotoSansJP-Regular.ttf` を置いておきます。`index.ts`を以下のように修正します。

```tsx
import * as fontkit from 'fontkit';

const font = fontkit.openSync('./NotoSansJP-Regular.ttf') as fontkit.Font;

const text = 'fontkitを試す';
const run = font.layout(text);

let cursorX = 0;
const paths = run.glyphs.map((glyph, index) => {
  const pos = run.positions[index];
  if (!pos) return '';

  const d = glyph.path.toSVG();
  const pathTag = d ? `<path d="${d}" transform="translate(${cursorX + pos.xOffset}, ${pos.yOffset})" />` : '';
  cursorX += pos.xAdvance;
  return pathTag;
}).filter(Boolean); // 空の要素（空白文字分）を配列から除外

// cursorX には最終的な横幅が入っているので、そのまま viewBox に利用
const svg = `<svg viewBox="0 0 ${cursorX} ${font.ascent - font.descent}" xmlns="http://www.w3.org/2000/svg">
  <g transform="translate(0, ${font.ascent}) scale(1, -1)">
    ${paths.join('\n    ')}
  </g>
</svg>`;

await Bun.write('output.svg', svg);
```

以下のコマンドで実行します。

```bash
$ bun run index.ts
```

実行後に生成された `output.svg` を開くと、↓のように表示されます。

![image1.png](/images/da5c80997a6d25/image1.png)

※ font.ascent と font.descent について

- font.ascent
  - ベースラインから、文字の**一番高いところ（頂点）までの距離**。アルファベットの「h」や「T」など、上に伸びる文字がすっぽり収まる高さを表す。
- font.descent
  - ベースラインから、文字の**一番低いところ（底辺）までの距離**。アルファベットの「g」「y」「p」のように、ベースラインよりも下に突き抜ける（ぶら下がる）文字のためのスペース

# 円形テキストにしてみる

次に少し応用して、↓のように文字を円形に並べて表示してみます。

![image2.png](/images/da5c80997a6d25/image2.png =500x)

先ほどの `index.ts` を以下に修正します。

```tsx
import * as fontkit from 'fontkit';

const font = fontkit.openSync('./NotoSansJP-Regular.ttf') as fontkit.Font;

const text = 'FontkitはNodeおよびブラウザ向けの高度なフォントエンジンでありPDFKitでも採用されています';
const run = font.layout(text);

let totalWidth = 0;
for (const pos of run.positions) totalWidth += pos.xAdvance;
// 円周から「半径 (radius)」を逆算する (円周 = 直径 × π)
const radius = totalWidth / (2 * Math.PI);

let cursorX = 0;
const paths = run.glyphs.map((glyph, index) => {
  const pos = run.positions[index];
  if (!pos) return '';
  const d = glyph.path.toSVG();

  const charCenter = cursorX + (pos.xAdvance / 2);
  // この文字が「360度のうち、何度（角度）の位置にいるべきか」を計算
  const angleDeg = (charCenter / totalWidth) * 360;

const pathTag = d ? `
    <g transform="rotate(${angleDeg}) translate(0, -${radius}) scale(1, -1)">
      <path d="${d}" transform="translate(${pos.xOffset - (pos.xAdvance / 2)}, ${pos.yOffset})" />
    </g>` : '';

  cursorX += pos.xAdvance;
  return pathTag;
}).filter(Boolean); // 空の要素（空白文字分）を配列から除外

// SVGのキャンバスサイズを、円がすっぽり収まるように設定 (0,0 を中心にする)
const margin = font.ascent;
const viewBoxSize = (radius + margin) * 2;
const offset = -(radius + margin);

const svg = `<svg viewBox="${offset} ${offset} ${viewBoxSize} ${viewBoxSize}" xmlns="http://www.w3.org/2000/svg">
  <style> path { fill: #2c3e50; } </style>
  <circle cx="0" cy="0" r="${radius}" fill="none" stroke="#e0e0e0" stroke-width="20" />
${paths.join('\n')}
</svg>`;

await Bun.write('circle.svg', svg);

```

修正後、再度以下のコマンドで実行すると `circle.svg` が生成されます。

```bash
$ bun run index.ts
```

円形に並べるポイントとなる部分は以下です。

```tsx
transform="rotate(${angleDeg}) translate(0, -${radius}) scale(1, -1)"
```

- `scale`：文字の上下方向を正しくする
- `translate`：文字を円の中心から半径分だけ上へ移動する
- `rotate`：円の中心を軸に、計算した角度まで回転する

つまり、各文字を一度12時の位置に置き、必要な角度だけ回転させることで、文字列を円形に並べています。

# まとめ

今回は`fontkit`を使い、Noto Sans JPのフォントファイルから日本語テキストをSVGパスへ変換しました。

- `font.layout()`でグリフと位置情報を取得できる
- `glyph.path.toSVG()`でグリフの輪郭をSVGパスへ変換できる
- 各グリフの位置と角度を計算すれば、円形のようなレイアウトにも応用できる

DOMやCanvasを使わずにSVG文字列を生成できるため、サーバーサイドなどで文字を描画したい場合にも活用できそうです。
