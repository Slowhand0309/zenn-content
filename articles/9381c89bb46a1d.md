# 概要

MacからUbuntu端末へSSH接続する際、秘密鍵をローカルファイルとして保存せず、**1Password SSH Agent**経由で認証する構成にしました。

最終的には、次のコマンドだけで接続できます。

```bash
ssh home-ubuntu
```

コマンドを実行すると1Passwordの認証画面が開き、Touch IDで承認するとUbuntuへログインできます。

> 🔐 **今回の構成**

# 動作環境

- MacBook Air（M3）

- macOS Tahoe 26.5.2

- Ubuntu 26.04 LTS（GNU/Linux 7.0.0-28-generic x86_64）

- 1Passwordデスクトップアプリ

- MacとUbuntuは同一LAN内

実際のIPアドレス、ユーザー名、ホスト名は伏せています。

# 1PasswordにSSHキーを用意する

1Passwordで「SSHキー」アイテムを作成します。既存の鍵をインポートしても、新しくEd25519鍵を生成しても構いません。

今回のような個人利用では、鍵の種類はEd25519で問題ありません。

1Passwordの設定からSSH Agentを有効にします。

```plain text
1Password
  → 設定
  → 開発者
  → SSHエージェントの設定
```

初回設定では、SSH接続の承認画面に鍵名を表示するため、キー名をローカルディスクへ保存するか確認されます。

- **キー名の使用**：複数の鍵を見分けやすい

- **キー指紋のみを使用**：鍵名を端末上へ残したくない場合に向いている

個人端末で鍵名に機密情報を含めていないため、今回は「キー名の使用」を選びました。

# SSH Agentで利用する保管庫を設定する

1PasswordのSSHキーアイテムに「SSHエージェントのキーを有効にする」と表示された場合は、「SSHエージェントの設定ファイルを開く」から対象の保管庫を追加します。

設定ファイルは通常、次の場所にあります。

```plain text
~/.config/1Password/ssh/agent.toml
```

たとえば、特定の保管庫にあるSSHキーを利用する場合は、1Passwordの画面からその保管庫を対象に設定します。

# 1Password SSH AgentをMacから参照する

1Password SSH Agentのソケットは、macOSでは次の場所にあります。

```plain text
~/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock
```

まず、Agentから鍵が見えるか確認します。

```bash
SSH_AUTH_SOCK="$HOME/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock" \
  ssh-add -l
```

鍵のフィンガープリントが表示されれば、1Password SSH Agent自体は正常です。

## `The agent has no identities.`になった場合

通常の`ssh-add -l`で次のように表示される場合があります。

```plain text
The agent has no identities.
```

このとき、現在の参照先を確認します。

```bash
echo "$SSH_AUTH_SOCK"
```

今回の環境では、次のようにmacOS標準のSSH Agentを参照していました。

```plain text
/var/run/com.apple.launchd.xxxxxxxxxx/Listeners
```

つまり、1Passwordに鍵がないのではなく、`ssh-add`が別のAgentを見ていたのが原因でした。

`ssh-add`などでも常に1Password Agentを使うため、`~/.zshrc`へ追加します。

```bash
# 1Password SSH Agent
export SSH_AUTH_SOCK="$HOME/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock"
```

設定を反映します。

```bash
source ~/.zshrc
ssh-add -l
```

> 💡 `~/.ssh/config`の`IdentityAgent`は`ssh`コマンドには効きますが、単体の`ssh-add`には適用されません。`ssh-add -l`でも1Passwordの鍵を確認したい場合は、`SSH_AUTH_SOCK`の設定が必要です。

# UbuntuでSSHサーバーを有効にする

Ubuntu側でOpenSSH Serverをインストールします。

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh --no-pager
```

UFWを有効にしている場合は、SSHを許可します。

```bash
sudo ufw allow OpenSSH
sudo ufw status
```

# Ubuntuへ公開鍵を登録する

1PasswordのSSHキーアイテムから**公開鍵**をコピーします。

Ubuntu側で次を実行します。

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys
```

コピーした公開鍵を1行で貼り付けます。

```plain text
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... 任意のコメント
```

権限を整えます。

```bash
chmod 600 ~/.ssh/authorized_keys
chown -R "$(id -un)":"$(id -gn)" ~/.ssh
```

Ubuntuへ登録するのは公開鍵だけです。秘密鍵をUbuntuへコピーする必要はありません。

# `ssh 短い名前`で接続できるようにする

Macの`~/.ssh/config`へ接続先を登録します。

```javascript
Host home-ubuntu
  HostName 192.168.x.x
  User ubuntu-user
  IdentityAgent "~/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock"
  IdentitiesOnly yes
```

- `Host`：普段入力する短い名前

- `HostName`：UbuntuのIPアドレスまたはホスト名

- `User`：Ubuntu側のログインユーザー

- `IdentityAgent`：1Password SSH Agentのソケット

- `IdentitiesOnly yes`：この接続で指定したAgentの鍵を使う

設定ファイルの権限も整えます。

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/config
```

SSHが認識している設定を確認できます。

```bash
ssh -G home-ubuntu | grep -Ei 'hostname|user|identityagent|identitiesonly'
```

# Touch IDでSSH接続する

準備ができたら、Macから次を実行します。

```bash
ssh home-ubuntu
```

初回接続時は、サーバーのホスト鍵を信頼するか確認されます。接続先に間違いがないことを確認して`yes`を入力します。

その後、1Passwordの承認画面が表示されます。Touch IDで承認すると、1Password内の秘密鍵による署名が行われ、Ubuntuへログインできます。

```plain text
ssh home-ubuntu
  ↓
1Passwordの認証画面
  ↓
Touch IDで承認
  ↓
Ubuntuへログイン
```

> ✨ 秘密鍵ファイルのパスやパスフレーズを毎回指定せず、`ssh home-ubuntu`だけで安全に接続できるようになりました。

# 接続できない場合の確認ポイント

## 1Passwordの鍵が見えるか

```bash
ssh-add -l
```

鍵が出ない場合は、Agentを直接指定して確認します。

```bash
SSH_AUTH_SOCK="$HOME/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock" \
  ssh-add -l
```

## SSH設定が反映されているか

```bash
ssh -G home-ubuntu | grep -i identityagent
```

## 詳細ログを確認する

```bash
ssh -vvv home-ubuntu
```

ログ内で、1Password Agentの鍵が候補として提示されているかを確認します。

## macOSのローカルネットワーク権限

LAN内のUbuntuへ接続する場合、利用しているターミナルアプリにmacOSのローカルネットワーク権限が必要になることがあります。

```plain text
システム設定
  → プライバシーとセキュリティ
  → ローカルネットワーク
```

Ghostty、iTerm2、Warpなど、実際に`ssh`を実行するアプリを許可します。

# まとめ

- 秘密鍵は1Passwordから取り出さず、SSH Agent経由で利用できる

- Ubuntuには公開鍵だけを登録する

- `IdentityAgent`で`ssh`の接続先を1Password Agentへ向ける

- `SSH_AUTH_SOCK`を設定すると、`ssh-add`なども1Password Agentを参照する

- `~/.ssh/config`へ接続先を登録すれば、`ssh home-ubuntu`だけで接続できる

- 1Passwordの画面をTouch IDで承認するとUbuntuへログインできる
