# 概要

Ubuntu環境でClaude Codeを定期実行したくなり、`cron`ではなく`systemd timer`を使って、毎日決まった時刻に`claude -p`を実行する構成を試しました。

今回作ったのは、Claude CodeがWeb検索を使ってその日の主要ニュースを3件調べ、`news.txt`へ保存する小さなジョブです。

最終的な構成は次の通りです。

```plain text
systemd timer
    ↓
oneshot service
    ↓
シェルスクリプト
    ↓
claude -p
    ↓
news.txtへ保存
```

> 💡 **今回のポイント**

# 動作環境

環境固有のユーザー名やディレクトリ名は一般化しています。

- Ubuntu

- Claude Codeインストール済み

- Claude Code認証済み

- ユーザー単位のsystemdを利用

- タイムゾーン：`Asia/Tokyo`

以下では、作業用ディレクトリを次のようにします。

```plain text
/home/exampleuser/projects/claude-news
```

# まずClaude Code単体で確認する

最初に、Claude Codeが非対話モードで動作するか確認します。

```bash
command -v claude
claude auth status --text
```

次に、簡単なプロンプトを実行します。

```bash
claude -p "こんにちは、と日本語で1行だけ返してください"
```

この段階で正常に応答すれば、Claude Code本体と認証は問題ありません。

# 作業ディレクトリを作成する

```bash
mkdir -p /home/exampleuser/projects/claude-news
cd /home/exampleuser/projects/claude-news
```

# ニュース取得スクリプトを作成する

`fetch-news.sh`を作成します。

```bash
nano /home/exampleuser/projects/claude-news/fetch-news.sh
```

内容は次の通りです。

```bash
#!/usr/bin/env bash

set -Eeuo pipefail

readonly OUTPUT_DIR="/home/exampleuser/projects/claude-news"
readonly OUTPUT_FILE="$OUTPUT_DIR/news.txt"
readonly CLAUDE_BIN="/home/exampleuser/.local/bin/claude"

mkdir -p "$OUTPUT_DIR"

TODAY="$(TZ=Asia/Tokyo date '+%Y-%m-%d')"
TEMP_FILE="$(mktemp "$OUTPUT_DIR/.news.txt.XXXXXX")"

trap 'rm -f "$TEMP_FILE"' EXIT

PROMPT=$(cat <<EOF
本日は${TODAY}、タイムゾーンは日本時間です。

WebSearchとWebFetchを使用して、今日の主要ニュースを3件調査してください。

条件:
- 日本国内、国際、テクノロジーなどから重要度の高いニュースを選ぶ
- 今日発生または今日報道されたニュースを優先する
- 今日のニュースが十分にない場合は直近24時間まで対象にする
- 信頼できる情報源を使用する
- 同じ出来事を重複して選ばない
- 推測や未確認情報は書かない
- 日本語で出力する

出力形式:

# ${TODAY}の主要ニュース

## 1. ニュースタイトル

- 概要:
- 重要な理由:
- 発生日時または報道日時:
- 情報源:
  - 媒体名: URL

## 2. ニュースタイトル

同じ形式で記載してください。

## 3. ニュースタイトル

同じ形式で記載してください。
EOF
)

printf '%s\n' "$PROMPT" |
  "$CLAUDE_BIN" -p \
    --no-session-persistence \
    --output-format text \
    --max-turns 10 \
    --tools "WebSearch,WebFetch" \
    --allowedTools "WebSearch,WebFetch" \
    > "$TEMP_FILE"

# ターミナルやjournalctlにも出力する
cat "$TEMP_FILE"

# 正常終了した場合だけ置き換える
mv "$TEMP_FILE" "$OUTPUT_FILE"

trap - EXIT
```

実行権限を付けます。

```bash
chmod 700 /home/exampleuser/projects/claude-news/fetch-news.sh
```

Claude Codeのパスは環境によって異なるため、次で確認します。

```bash
command -v claude
```

結果に合わせて、スクリプト内の`CLAUDE_BIN`を変更します。

# 直接実行して確認する

systemdへ進む前に、必ずスクリプト単体で確認します。

```bash
/home/exampleuser/projects/claude-news/fetch-news.sh
```

生成結果を確認します。

```bash
cat /home/exampleuser/projects/claude-news/news.txt
```

# 失敗1：プロンプトが渡されていない

最初は次のエラーになりました。

```plain text
Error: Input must be provided either through stdin or as a prompt argument when using --print
```

当初は、コマンド末尾にプロンプトを渡していました。

```bash
claude -p \
  --tools "WebSearch,WebFetch" \
  --allowedTools "WebSearch" "WebFetch" \
  "$PROMPT"
```

しかし、オプションの解釈によってプロンプトが正しく渡らず、Claude Code側では入力なしとして扱われました。

そこで、プロンプトを標準入力から渡す形へ変更しました。

```bash
printf '%s\n' "$PROMPT" |
  claude -p \
    --tools "WebSearch,WebFetch" \
    --allowedTools "WebSearch,WebFetch"
```

この形にすると、長い複数行プロンプトでも安定して渡せました。

> ⚠️ `claude -p`で複数行プロンプトをスクリプトから渡す場合は、標準入力を使うとトラブルが少なくなります。

# systemdのoneshotサービスを作る

ユーザー単位のUnitファイルを作成します。

```bash
mkdir -p ~/.config/systemd/user
nano ~/.config/systemd/user/claude-news.service
```

内容は次の通りです。

```plain text
[Unit]
Description=Fetch today's major news using Claude Code

[Service]
Type=oneshot
Environment=HOME=/home/exampleuser
Environment=TZ=Asia/Tokyo
WorkingDirectory=/home/exampleuser/projects/claude-news
ExecStart=/home/exampleuser/projects/claude-news/fetch-news.sh
TimeoutStartSec=15min
UMask=0077
```

`Type=oneshot`は、1回実行して終了するジョブに向いています。

`UMask=0077`を指定しているため、生成されるファイルは基本的に実行ユーザーだけが読み書きできます。

# 失敗2：ExecStartに環境変数を書いた

最初のServiceでは、次のように書いていました。

```plain text
ExecStart=$HOME_DIR/fetch-news.sh
```

すると、Serviceの設定エラーとなり、Timerも起動できませんでした。

ログには次のような内容が出ていました。

```plain text
Unit configuration has fatal error
Refusing to start, unit configuration has fatal error
```

原因は、`ExecStart`が通常のシェルとして評価されないことでした。

`$HOME_DIR`のようなシェル変数は自動展開されません。また、このUnit内では`HOME_DIR`自体も定義していませんでした。

そのため、`ExecStart`には絶対パスを指定しました。

```plain text
ExecStart=/home/exampleuser/projects/claude-news/fetch-news.sh
```

同様に、`WorkingDirectory`も絶対パスへ揃えています。

> 🔍 **systemdで意識すること**

# Serviceを手動実行する

設定を再読み込みします。

```bash
systemctl --user daemon-reload
systemctl --user reset-failed
```

Unitファイルを検証します。

```bash
systemd-analyze --user verify \
  ~/.config/systemd/user/claude-news.service
```

問題がなければ、Serviceを手動実行します。

```bash
systemctl --user start claude-news.service
```

状態確認はこちらです。

```bash
systemctl --user status claude-news.service \
  --full \
  --no-pager
```

ログは次で確認できます。

```bash
journalctl --user \
  -u claude-news.service \
  -n 100 \
  --no-pager
```

`Type=oneshot`の場合、成功後に次のように表示されても正常です。

```plain text
Active: inactive (dead)
status=0/SUCCESS
```

処理が完了して終了したため、`inactive`になっています。

# 毎日17時に実行するTimerを作る

```bash
nano ~/.config/systemd/user/claude-news.timer
```

内容は次の通りです。

```plain text
[Unit]
Description=Run Claude news job every day at 17:00

[Timer]
OnCalendar=*-*-* 17:00:00
Persistent=true
Unit=claude-news.service

[Install]
WantedBy=timers.target
```

設定内容は次の通りです。

- `OnCalendar=*-*-* 17:00:00`：毎日17時に実行

- `Persistent=true`：17時にマシンが停止していた場合、次回起動時に未実行分を実行

- `Unit=claude-news.service`：対象のoneshotサービスを指定

次回実行時刻は事前に確認できます。

```bash
systemd-analyze calendar '*-*-* 17:00:00'
```

# Timerを有効化する

```bash
systemctl --user daemon-reload
systemctl --user enable --now claude-news.timer
```

状態確認はこちらです。

```bash
systemctl --user status claude-news.timer \
  --full \
  --no-pager
```

次回実行時刻を確認します。

```bash
systemctl --user list-timers claude-news.timer
```

# SSH切断後も動かす

ユーザー単位のsystemdは、環境によってはログアウト後に停止します。

SSH切断後や再起動後もTimerを動かすため、lingerを有効にします。

```bash
sudo loginctl enable-linger "$USER"
```

確認します。

```bash
loginctl show-user "$USER" -p Linger
```

次のようになれば有効です。

```plain text
Linger=yes
```

# 今回ハマった点まとめ

| 症状 | 原因 | 解決 |
| --- | --- | --- |
| `Input must be provided...` | プロンプトが`claude -p`へ正しく渡っていなかった | `printf`から標準入力で渡す |
| Serviceの設定エラー | `ExecStart=$HOME_DIR/...`と書いていた | 絶対パスを指定する |
| Timerが起動拒否される | 呼び出し先Serviceに構文エラーがあった | `systemd-analyze verify`で先にServiceを確認する |
| 成功後に`inactive (dead)` | `oneshot`が正常終了した | `status=0/SUCCESS`なら正常 |

# まとめ

Claude Codeの定期実行は、`systemd timer`と`claude -p`を組み合わせることで、比較的シンプルに構成できました。

最初からTimerまで一気に作るより、次の順番で確認するとトラブルを切り分けやすいです。

1. `claude -p`を直接実行する

1. シェルスクリプトを直接実行する

1. oneshotサービスを手動実行する

1. 最後にTimerを有効化する

特に、systemdはシェルスクリプトと同じ感覚で書くと、環境変数やリダイレクト周りでハマりやすいです。

実処理をシェルスクリプトへ分離し、Service側は絶対パスでそのスクリプトを呼び出す形にすると、かなり分かりやすくなりました。

今回は通常のClaude Code認証情報を利用していますが、次の段階では1Password CLIやService Accountを使い、実行時だけ秘匿情報を注入する構成も試してみたいと思います。
